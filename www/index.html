Zoraxy Cloudflare WAF plugin

Mirrors abusive clients from Zoraxy's access log and blacklist events into a Cloudflare IP List.
How this works (read this first)

What it does

  • Follows Zoraxy's access log (from the moment the plugin starts) and, if ticked, Zoraxy's own blacklist events.
  • A client IP becomes a block candidate when (1) a request looks like an exploit probe (path traversal, /etc/passwd, actuator endpoints, etc.); (2) it asks for a file only scanners ask for — /.git/…, /.env, /.aws//.docker//.kube//.ssh, .netrc/.npmrc, credential files, SSH keys — whatever the response status (single-page apps answer such paths with 200, so error counts alone miss those scanners); or (3) it racks up more than the threshold of 4xx/5xx responses within the window (see Detection thresholds).
  • Private, loopback and Cloudflare's own addresses are never blocked. An IP already actioned is skipped until the re-block cooldown passes.
  • Two layers, independent: Cloudflare's edge (primary) and, optionally, Zoraxy's own blacklist. If one layer fails and the other works the action shows as partial, and the failing layer's reason is in the Detail column.
  • Blocks expire after the number of days you set (default 14); only entries this plugin created are removed.

Off, dry run, live

  • Enabled off — nothing is acted on.
  • Enabled + Dry run — decisions are recorded and logged but nothing is sent to Cloudflare. This is the safe way to watch what it would do.
  • Enabled, Dry run off (live) — the first real block creates the IP list and one WAF custom rule in Cloudflare (if they don't exist), then adds the IP to the list. Until then Cloudflare shows nothing new — that's expected.

Where to see what it's doing

  • The Recent actions table at the bottom of this page (kept in memory — it empties when Zoraxy or the plugin restarts).
  • The Zoraxy journal, which keeps history: journalctl -u zoraxy -f | grep -F "Zoraxy Cloudflare WAF plugin". A "logtail: alive" line appears every 30 minutes as a heartbeat.

Names — two different fields

  • IP list name is a machine name Cloudflare uses inside the rule expression: letters, digits and underscores only, no spaces.
  • WAF rule name is just the label in Cloudflare's Security Rules list — spaces and capitals are fine. Use a name none of your own rules has. The plugin only ever edits the rule it created. If one of your rules already has exactly this name, it is left untouched, the plugin's rule is not created, and blocks are reported as errors (Test Connection warns you up front).

Good to know

  • Test Connection checks what is typed in the boxes but does not save it — click Save afterwards.
  • A changed Block action reaches Cloudflare at the next real block, not when you save.
  • Cloudflare limits how many lists an account can have (Free plans very few — a separate limit from the 5 custom rules). If it is used up, the first block fails with "maximum number of lists"; Test Connection shows your lists and warns. Free one, or point IP list name at an existing IP list that is only a block list.
  • Changes to the log directory or detection thresholds need the plugin to be restarted.

Behaviour
Many scanners use rented cloud addresses that are later reused by legitimate services, so a permanent block slowly becomes a false positive. Only entries this plugin added are ever removed — never ones you added by hand. Removal runs hourly and only while live (not in dry run).

Needs a scoped token (never the Global API Key) with exactly two permissions: Account → Account Filter Lists → Edit and Zone → WAF → Edit, scoped to this account and this zone. Create one at https://dash.cloudflare.com/profile/api-tokens → "Create Custom Token".
Both IDs are on the zone's Overview page in the Cloudflare dashboard, right-hand sidebar. They are masked like the token (safer on a shared screen) — use Show to check them; they re-hide after 15 seconds.

Cloudflare's own current limits (Free/Pro/Business, verify against your plan): 5 custom rules per zone, 10,000 items total across all custom IP lists on the account, and a 4,096-character expression limit per rule. This plugin's design (one list, one rule referencing it) keeps the rule's expression under 40 characters regardless of list size, so the character limit is never the real constraint — the list's 10,000-item cap is. The field above stops this plugin from even trying past that cap; a full list shows as skipped-list-full below instead of erroring.
Zoraxy's own blacklist (optional second layer)
Bans go into the blacklist of the access rules you tick below and expire with the setting above. Two things must be true for a ban to work: the rule's blacklist must be switched on, and Zoraxy must see the visitor's real address — behind a Cloudflare tunnel that means the address the tunnel connects from (this server's own addresses, e.g. 127.0.0.1 and its LAN IP) must be in Zoraxy's Trusted Proxies, with the rule's Trust proxy headers only on. See the README ("Zoraxy's own blacklist"). Uses the API permissions Zoraxy lists for this plugin — restart Zoraxy once after installing this version.
